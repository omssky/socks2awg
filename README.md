# socks2awg

Небольшой менеджер персональных **SOCKS5 → AmneziaWG** туннелей.
Один РУ-сервер, отдельный SOCKS-порт и AWG-конфиг для каждого коллеги.
Для рабочих агентов, которым нужен постоянный зарубежный выход.

```text
Агент Alice → RU:11001 + пароль → wireproxy-awg Alice → AWG-нода Alice
Агент Bob   → RU:11002 + пароль → wireproxy-awg Bob   → AWG-нода Bob
```

Bash-утилита с меню; один контейнер на профиль. Без веб-панели, домена,
базы данных и постоянно работающего управляющего сервиса.
Сам туннель обслуживает [wireproxy-awg](https://github.com/artem-russkikh/wireproxy-awg).

## Установка

Целевая платформа: Linux, Ubuntu 24.04 / Debian 12–13, root и Docker с Compose plugin
(`docker compose`). Другие версии требуют отдельной проверки. macOS — только для разработки.

**Из root-shell на сервере:**

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/omssky/socks2awg/master/install.sh)
```

Установщик предложит установить Docker из его официального apt-репозитория,
если Docker отсутствует. Уже установленный Docker не заменяется и не перезапускается.
При отсутствии только Compose plugin установщик попросит установить совместимый plugin.

При первой установке образ ядра собирается из закреплённого upstream-коммита.
Это требует доступа к GitHub, Go-модулям и реестрам Docker; сборка расходует
больше CPU, памяти и диска, чем последующий запуск. Образ общий для всех профилей.
Готовый образ в публичном registry пока не публикуется.

Установка из локального checkout:

```bash
sudo bash install.sh --from "$PWD"
```

Для установки Docker без вопроса можно добавить `--install-docker`.
Установка через `sudo bash <(...)` не рекомендуется: используйте root-shell
или скачайте `install.sh` в файл и вызовите `sudo bash install.sh`.

После установки:

```bash
sudo socks2awg
```

При первом запуске укажите публичный **IPv4 или домен** РУ-сервера.
Это только адрес в выдаваемых ссылках; домен и сертификат не нужны.
IPv6 SOCKS-вход в первой версии не поддерживается.

## Меню

```text
socks2awg 0.1.0

1. Добавить профиль
2. Выбрать профиль
3. Статистика всех профилей
4. Проверить все подключения
0. Выход
```

В карточке профиля:

```text
alice · SOCKS :11001 · running

1. Данные подключения (покажет пароль)
2. Статистика
3. Проверить подключение
4. Последние логи
5. Остановить / Запустить
6. Удалить профиль
0. Назад
```

Изменения настроек нет: сохраните исходный AWG-конфиг, удалите профиль и добавьте заново.
Это прерывает его соединения и генерирует **новый SOCKS-пароль**. Для сохранения номера порта
укажите `--port`. Другие профили не перезапускаются.

## Добавление: вставить текст или передать файл

### Вставка

```bash
sudo socks2awg add alice
```

Вставьте обычный AWG `.conf`; завершите отдельной строкой `END`.
Ввод **виден в терминале**, но не передаётся оболочке для исполнения и не записывается
в её историю команд. Не вставляйте конфиг в общий/записываемый терминал.

### Файл

На своём компьютере:

```bash
scp ~/Downloads/alice.conf root@SERVER_IP:/root/alice.conf
```

На сервере:

```bash
socks2awg add alice /root/alice.conf
# Или назначить порт вручную:
socks2awg add bob /root/bob.conf --port 11002
```

Утилита сохраняет собственную копию: исходный файл после успешного импорта можно удалить.
Автоматические SOCKS-порты: 11001–19999; ручной порт: 1024–65535.
Пароль — 24 случайных байта, представленных 48 hex-символами. Логин совпадает с именем.
Остановленные профили сохраняют свои порты. Повторный импорт того же AWG private key отклоняется.

### Поддерживаемый конфиг

Один `[Interface]`, один `[Peer]`, `AllowedIPs` должен включать `0.0.0.0/0`.
Поддерживаются параметры AWG 1–3.1, реализованные закреплённой версией wireproxy-awg;
сервер и клиент должны иметь согласованные параметры. Также работает обычный WireGuard.
Форматы `vpn://`, зашифрованные экспорты приложения, подписки и VLESS не поддерживаются.

Конфиг проверяется до создания профиля; файл с ошибкой не заменяет другие профили.
Неизвестные параметры, дополнительные секции и команды `PreUp`/`PostUp`/`PreDown`/`PostDown`
отклоняются. `Table` и `SaveConfig` пропускаются как настройки wg-quick;
`ListenPort` заменяется на `0`, чтобы клиенты не занимали одинаковый UDP-порт.
Если `DNS` отсутствует, добавляется `1.1.1.1` **внутри туннеля**.
DNS-адреса должны быть IP, не доменами. Разрешение домена самого AWG endpoint, если он есть,
выполняется средствами РУ-хоста до установки туннеля.

Не используйте тот же AWG peer одновременно на ноутбуке и на РУ-сервере:
для профиля нужен отдельный клиентский конфиг от зарубежной ноды.

## Команды

```text
socks2awg                            меню
socks2awg add NAME [FILE] [--port N]  добавить
socks2awg list                       список и статус контейнеров
socks2awg show NAME                  адрес, пароль и socks5h:// URL
socks2awg check [NAME]               проверить один профиль / все
socks2awg stats [NAME] [--watch]      статистика одного профиля / всех
socks2awg logs NAME                  последние 100 строк
socks2awg start NAME                 запустить
socks2awg stop NAME                  остановить
socks2awg remove NAME [--yes]         удалить; по умолчанию с подтверждением
socks2awg help                       справка
socks2awg version                    версия
```

`check` делает HTTPS-запрос к `https://api.ipify.org` через SOCKS с удалённым DNS
и показывает IP выхода. Успех означает, что запрос прошёл через туннель; страна автоматически
не определяется. Сбой сервиса проверки также приводит к ошибке проверки.
При необходимости адрес IP-echo сервиса можно заменить через `SOCKS2AWG_CHECK_URL`
(HTTPS; тело ответа должно содержать только IP).

Проверка с РУ-сервера не проверяет доступность входящего SOCKS-порта из вашей сети.
При сетевой ошибке после `add` профиль сохраняется для диагностики, а команда возвращает
ненулевой код. При ошибке разбора/валидации профиль не создаётся.

## Статистика

CPU, RAM, время работы контейнера, RX/TX и время последнего AWG handshake.
В меню экран обновляется с паузой около 3 секунд между выборками;
Enter возвращает в меню. В CLI без `--watch` выводится одна выборка.

Трафик считается по AWG peer, включая служебные данные, **с запуска ядра**.
После перезапуска ядра счётчики обнуляются. Недоступные показатели обозначаются прочерком,
а не нулём. Истории по дням, графиков и расчёта текущей скорости в v0.1 нет.

Ресурсы берутся из `docker stats`, трафик — из встроенного `/metrics` wireproxy-awg.
Служебные порты 31001–39999 слушают только `127.0.0.1`.
Секретные ключи не выводятся в статистике. Запущенный контейнер и недавний handshake
не заменяют успешную проверку `check`.

## Сеть и хранение

Контейнеры используют Linux `network_mode: host`: нет NAT/проброса Docker-портов,
TUN-интерфейсов, `NET_ADMIN` или изменения маршрута по умолчанию на хосте.
Это отдельные процессы и конфиги, **не отдельные сетевые пространства**.
Контейнер запускается с read-only filesystem, без Linux capabilities и с
`no-new-privileges`; UID 0 используется для чтения root-owned конфигурации `0600`.

SOCKS слушает `0.0.0.0:PORT` и требует логин/пароль. Утилита не управляет фаерволлом
или SSH: самостоятельно разрешите выбранные TCP-порты в уже используемом фаерволле
сервера/хостера. Открывать порты `/metrics` наружу не нужно.
Первая установка самого Docker может создать его штатные сетевые правила.

SOCKS5 сам по себе не шифрует участок клиент → РУ-сервер, включая SOCKS-пароль.
HTTPS-трафик агента остаётся защищён TLS, а участок РУ → нода защищён AWG.
Только TCP через SOCKS: SOCKS UDP в этой версии ядра не поддерживается.

```text
/usr/local/bin/socks2awg               установленная команда
/opt/socks2awg/current/                текущая версия утилиты
/opt/socks2awg/versions/                установленные версии
/var/lib/socks2awg/host                 адрес сервера для ссылок
/var/lib/socks2awg/profiles/alice/
    source.conf                       исходный импорт
    awg.conf                          нормализованный AWG-конфиг
    wireproxy.conf                    AWG + SOCKS с авторизацией
    profile.json                      порт, пароль и метаданные
    compose.json                      Compose-файл одного профиля
```

JSON допустим как формат Compose-файла; генерируется через `jq`, без ручного экранирования YAML.
Каталоги данных — `0700`, файлы — `0600`. Команды изменения сериализуются через `flock`.
Логи ограничены двумя файлами по 5 MiB на контейнер. Профили используют `unless-stopped`:
запущенные поднимутся после перезагрузки, вручную остановленные останутся остановленными.

## Обновление и резервная копия

Повторите установку. Код переключается после проверки пакета и успешной сборки ядра;
конфиги и существующие контейнеры сохраняются. Обновление утилиты не обновляет образ
в уже созданных профилях и не прерывает их соединения. Для перехода профиля на новое ядро
нужно пересоздать его. Дистрибутив ядра закреплён на коммите
`84f4795ea76f9c3168a61e478d0fe0e5c3238308`; базовые Docker-образы используют версии-теги.

Резервная копия данных содержит **все секреты**. Выполняйте от root:

```bash
umask 077
flock /var/lib/socks2awg/.lock tar -czf /root/socks2awg-backup.tar.gz -C /var/lib socks2awg
```

При восстановлении нужен тот же путь `/var/lib/socks2awg` и образы, указанные в `compose.json`.
Установите ту же версию утилиты/ядра, восстановите архив и запустите нужные профили.
Не запускайте исходный сервер и его восстановленную копию одновременно с теми же AWG-ключами.

## Разработка и проверки

Зависимости runtime: Bash, Docker/Compose, curl, jq, openssl, awk, util-linux, iproute2.
Python нужен только тестам. Для CLI нет Go/Python runtime или npm-пакетов.

```bash
python3 -m unittest discover -s tests -p test_cli.py -v
shellcheck -x bin/socks2awg install.sh lib/*.sh
```

Тесты CLI используют реальные Bash-функции с подменённой границей Docker/curl.
Отдельный интеграционный тест поднимает два **настоящих AWG peer** и локальный HTTPS endpoint,
проверяет передачу через SOCKS, отказ без пароля/с неверным паролем и метрики.
Публичные VPN-ноды и пользовательские ключи для теста не нужны.

```bash
# Linux, Docker; запускать от root на машине для тестирования:
docker build -t socks2awg/wireproxy:84f4795ea76f -f engine/Dockerfile .
sudo env WIREPROXY_IMAGE=socks2awg/wireproxy:84f4795ea76f python3 tests/test_engine.py -v

# Или с локально собранным wireproxy (без Docker):
WIREPROXY_BINARY=/path/to/wireproxy python3 tests/test_engine.py -v
```

GitHub Actions запускает ShellCheck, тесты CLI, проверку Compose и интеграцию с Docker.

Контейнерная установка, переустановка с работающим профилем и сквозной тест проверены
на Ubuntu 24.04 arm64. Сборка Linux amd64 также проверена; CI повторяет интеграцию на amd64.
Debian указан как целевая платформа установщика, отдельный прогон на нём ещё не выполнен.
